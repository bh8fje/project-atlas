# Dashboard 设计原则

Project Atlas Dashboard 的目标是帮助用户理解项目，而不是用仪表和图形营造系统已经完成实时分析的错觉。

## 信息层次

Dashboard 将信息分为四类：

1. 项目建设：展示 Project Atlas 本身的建设阶段和已实现功能。
2. 发布记录：展示最近版本、测试和提交时状态。
3. 项目组成：说明 Project Atlas 包含的代码仓库、核心功能和本地资料。
4. 受控操作：只展示已明确注册的操作，修改前需要确认并保留记录。

## 必须区分的概念

- 发布记录不等于实时状态。
- 项目组成不等于项目关系。
- 项目内部的包含关系不等于多个项目之间的依赖或引用关系。
- 静态示意不等于自动扫描或 AI 分析结果。

## 真实性要求

- 所有数字必须标明来源或属于哪次发布。
- 静态内容必须明确标记为“示意”或“发布记录”。
- 没有数据支持时，不得伪造实时分析结果、健康分数或系统运行状态。
- 未接入核心数据源前，Dashboard 保持本地、只读且不进行隐式分析。

## 与项目目标的一致性

这套设计支持 Project Atlas 的本地优先、用户可控、可追踪和逐步演进原则。当未来接入项目发现、历史和关系数据时，必须通过明确任务替换相应的静态发布记录，不得让两种数据在界面中混淆。
