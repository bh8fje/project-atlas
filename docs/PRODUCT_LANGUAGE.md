# 产品文案规则

Project Atlas 面向用户的文案以中文为准，目标是让没有技术背景的人第一次看到就能明白。

## 写作顺序

1. 先写清楚、自然的中文。
2. 确认中文说明的是“用户能看到什么、能做什么、会发生什么”。
3. 再按中文含义翻译成英语、俄语和韩语。
4. 翻译不得自行增加技术术语或改变含义。

## 中文要求

- 使用常见词和短句。
- 优先说明结果，不先介绍内部实现。
- 能说“可以更换 AI 服务”，就不说“供应商无关”。
- 能说“每次操作都有记录”，就不说“可审计”。
- 能说“修改前必须确认”，就不说“显式副作用边界”。
- 产品名称、版本号和确有必要的技术名词可以保留，但要配上易懂说明。

## 适用范围

这些规则适用于 Dashboard、提示、按钮、帮助说明和其他直接面向用户的内容。代码、测试和架构决策文档可以使用准确的工程术语，但不得把这些术语直接搬进用户界面。
