# 产品文案规范

Project Atlas 面向用户的文案以中文为准。文案应专业、清晰、准确，不要滥用技术术语，也不要为了易懂而过度口语化。

## 写作顺序

1. 先写专业、清晰的中文。
2. 确认中文说明的是“用户能看到什么、能做什么、会发生什么”。
3. 再按中文含义翻译成英语、俄语和韩语。
4. 翻译不得自行增加技术术语或改变含义。

## 表达尺度

- 使用准确的常见词和简洁句式。
- 优先说明结果，不先介绍内部实现。
- 模块、阶段和功能名称优先使用稳定、专业的名词短语，例如“基础架构”，不使用“打好基础”这类口号式表达。
- 不追求“像聊天一样”；必要的专业词可以保留，但必须让用户能理解。
- 能说“可以更换 AI 服务”，就不说“供应商无关”。
- 能说“每次操作都有记录”，就不说“可审计”。
- 能说“修改前必须确认”，就不说“显式副作用边界”。
- 产品名称、版本号和确有必要的技术名词可以保留，但要配上易懂说明。
- 数字、状态和分析结论必须说明数据来源与时效性，静态记录不得写成实时结论。

## 适用范围

这些规则适用于 Dashboard、提示、按钮、帮助说明和其他直接面向用户的内容。代码、测试和架构决策文档可以使用准确的工程术语，但不得把难以理解的内部术语直接搬进用户界面。
