# ADR-0007：通过相对路径比较项目结构变化

- 状态：Accepted
- 日期：2026-08-23
- Task：TASK-008

## 背景

TASK-007 已建立 Change 契约，但尚无机制把两个结构状态转换为明确的新增、删除和修改记录。结构分析产生的一次性 Artifact ID 每次不同，不能作为跨时点比较键；变化检测也不能隐式扫描项目，否则比较边界和结果将不可复现。

## 决策

建立 `ChangeDetectionEngine`：

- 调用者显式提供前后两份 `ProjectStructure` 和对应 Snapshot ID。
- 使用相对于各自项目根目录的规范路径作为资产比较键。
- 路径只存在于后态时生成 `ADDED`，只存在于前态时生成 `REMOVED`。
- 同一路径的名称、资产类型、创建时间或修改时间不同时生成 `MODIFIED`。
- 忽略单次分析使用的 Artifact ID。
- 输出按路径排序，并根据项目、Snapshot、路径和变化类型生成确定性 Change ID。
- 初始状态允许前态和来源 Snapshot ID 同时为空，此时所有资产均为新增。

## 边界

- 不扫描文件系统，不读取文件内容。
- 不自动创建 Snapshot 或 Event。
- 不保存检测结果，不生成时间线。
- 不调用 Git、AI、数据库、API 或 UI。
- 重命名当前表达为一次删除和一次新增，不推断移动关系。

## 后果

正面影响：

- 相同输入产生稳定、有序的 Change 结果。
- 临时 Artifact ID 不影响跨分析比较。
- 检测逻辑与结构采集、历史存储和时间线展示保持解耦。

限制：

- 修改判断受 `ProjectArtifact` 当前元数据粒度限制，不进行内容级比较。
- 目录元数据变化也可能被记录为 `MODIFIED`。
- 不推断重命名、复制或语义变化。
