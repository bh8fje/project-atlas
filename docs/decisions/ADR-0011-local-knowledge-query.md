# ADR-0011：以结构化过滤和本地关键词匹配查询知识

- 状态：Accepted
- 日期：2026-08-23
- Task：TASK-012

## 背景

本地知识记录已经可以持久化，但调用者只能使用存储层的基础精确过滤。系统需要稳定的查询契约，并允许用户用普通文本查找记录。Phase 4 才引入 AI，因此当前“自然语言”能力必须明确限制为可解释的本地文本匹配。

## 决策

建立 `KnowledgeQuery`、`KnowledgeQueryResult` 与 `KnowledgeQueryEngine`：

- 结构化条件支持记录类型、Project ID、起止时间和结果数量限制。
- 可选文本被拆分为 Unicode 词项，并进行大小写无关的“全部词项匹配”。
- 匹配范围包括记录 ID、类型、Project ID 和规范 JSON 数据。
- 结果保持存储层的时间、类型、记录 ID 稳定顺序。
- 结果同时报告限制前的匹配总数，并支持完整序列化。
- 查询只读取 `LocalKnowledgeStore`，不修改任何记录。

## 边界

- 文本查询不是语义理解，不进行同义词、意图或相关性推断。
- 不调用 AI、嵌入模型或外部搜索服务。
- 不提供 SQL、图查询语言、全文索引、分页游标或聚合分析。
- 不提供 API、Dashboard 或 UI。

## 后果

正面影响：

- 查询行为完全本地、确定且可解释。
- 结构化与普通文本入口共享同一稳定结果契约。
- TASK-013 可以在查询结果上构建受控 AI 上下文。

限制：

- 数据量增大后，内存过滤需要替换为索引或数据库下推。
- 多词查询要求所有词项出现，不提供相关性排序。
- 中文等无空格文本按连续词项匹配，不进行分词语义分析。
