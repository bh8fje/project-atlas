# ADR-0008：以已验证事件构建确定性项目时间线

- 状态：Accepted
- 日期：2026-08-23
- Task：TASK-009

## 背景

Snapshot、Change 和 Event 已能表达项目历史事实，但调用者仍需要一个统一、可重复的时间顺序视图。时间线不能依赖存储返回顺序，也不能接受指向不存在对象的悬空引用；同时本阶段不应引入持久化或查询系统。

## 决策

建立 `ProjectTimeline` 与 `ProjectTimelineBuilder`：

- 调用者显式提供同一 Project 的 Snapshot、Change 与 Event 集合。
- 构建前校验对象所属项目、ID 唯一性及 Event/Change 的 Snapshot 和 Change 引用。
- Event 按 `occurred_at` 升序排列，同一时间使用 Event ID 作为稳定次序。
- `ProjectTimeline` 保存项目 ID、生成时间和不可变事件序列，并支持校验与序列化。
- 生成时间不得早于时间线中的最后一个事件。

## 边界

- 不自动采集、生成或修改历史事实。
- 不读写数据库或文件，不实现保留策略。
- 不提供过滤、搜索、分页或自然语言查询。
- 不建立跨项目关系图，不调用 Git、AI、API 或 UI。

## 后果

正面影响：

- 相同输入始终产生相同的事件顺序。
- 悬空引用和跨项目混用在进入时间线前被拒绝。
- 后续存储与界面可以依赖稳定的时间线领域契约。

限制：

- 当前时间线完全由调用者提供的内存对象生成。
- 相同时间事件的 ID 次序是确定性规则，不代表业务因果关系。
- 尚无聚合、摘要或查询优化。
