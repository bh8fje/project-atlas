# ADR-0005：基于路径身份和元数据的项目指纹

- 状态：Accepted
- 日期：2026-08-23
- Task：TASK-006

## 背景

项目发现与结构分析可以描述“项目在哪里”和“项目由什么组成”，但每次发现若产生随机 ID，系统无法稳定识别同一本地项目；如果没有可重复的状态摘要，后续也无法建立变化检测基础。此阶段仍禁止实现历史事件、Git 分析或内容语义分析。

## 决策

建立 `ProjectIdentityGenerator`、`ProjectFingerprintGenerator` 与 `ProjectFingerprint`：

- 对规范化后的本地项目根目录 URI 使用 UUID5，生成同一路径下可重复的稳定项目身份。
- 发现引擎创建 `Project` 时复用该稳定身份。
- 使用带版本号的 `sha256-metadata-v1` 算法生成结构状态摘要。
- 摘要输入只包含排序后的相对路径、资产类型、文件大小和纳秒修改时间。
- 指纹记录项目身份、算法、摘要、生成时间和资产数量，并支持校验、序列化与状态匹配。

## 边界

- 不读取或散列文件内容。
- 不调用 Git，不读取 commit、branch 或历史。
- 不持久化指纹，不建立 Snapshot、Event、Change 或时间线。
- 不判断具体增加、删除或修改；TASK-008 才负责变化检测。
- 项目移动到新路径会获得新身份，这是当前本地优先身份策略的明确限制。

## 后果

正面影响：

- 同一路径的重复发现具有稳定 Project ID。
- 临时 Artifact ID 不会影响结构指纹的可重复性。
- 后续 Snapshot 和变化检测获得版本明确、可序列化的输入契约。

限制：

- 如果文件内容变化但大小和修改时间均未变化，当前元数据指纹无法识别。
- 项目移动或根路径重命名会被视为新的本地项目身份。
- 算法输入变化时必须引入新的算法版本，不能静默改变既有语义。
