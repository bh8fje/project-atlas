# ADR-0003：显式边界的本地项目发现

- 状态：Accepted
- 日期：2026-08-23
- Task：TASK-004

## 背景

Project Atlas 需要先发现本地软件项目，后续结构分析、历史重建和 AI 理解才有明确输入。发现过程会读取用户文件系统，因此扫描范围、深度、符号链接和排除目录必须可预测，不能默认遍历整台设备。

## 决策

建立 `LocalProjectDiscoveryEngine` 与 `DiscoveryScope`：

- 每次发现必须显式提供一个或多个根目录。
- 扫描深度必须有非负上限，默认最大深度为 4。
- 通过 `.git`、`pyproject.toml`、`package.json`、`Cargo.toml` 或 `go.mod` 判断候选项目根目录。
- 发现项目标记后创建 `Project`，并停止深入该项目目录。
- 默认跳过版本控制元数据、依赖、虚拟环境、缓存和构建目录。
- 不跟随目录符号链接，避免越过调用方可见的扫描边界。
- 不可读取的子目录被安全跳过；无效的显式根目录直接报告错误。

## 边界

- 本 Task 只识别候选项目根目录，不分析文件结构或技术栈。
- 不运行 Git 命令，不读取 commit 或 branch。
- 不生成稳定项目指纹；当前 Project ID 是一次性 UUID，稳定身份留给 TASK-006。
- 不持久化结果，不调用 AI，不提供 API 或 UI。
- 测试只扫描临时目录，不扫描用户真实项目。

## 后果

正面影响：

- 扫描行为有明确、可测试的边界。
- 发现结果直接复用核心 `Project` 领域契约。
- 后续分析能力可以消费发现结果，而不重复处理文件系统边界。

限制：

- 只使用明确标记识别项目，可能遗漏没有标记文件的项目。
- 发现项目后不继续识别其内部嵌套项目。
- 同一项目在不同发现运行中会获得不同临时 ID。
