# ADR-0001：先建立核心领域模型

- 状态：Accepted
- 日期：2026-08-23
- Task：TASK-002

## 背景

Project Atlas 后续会涉及项目发现、项目理解、历史重建和关系分析。如果这些能力各自定义 Project、Task 和状态含义，系统会形成不一致的数据结构，增加持久化、接口和迁移成本。

## 决策

在实现任何发现或分析能力前，先建立无外部依赖的核心领域模型：

- `Project` 表示一个软件项目资产。
- `Task` 表示一次工程任务，并定义最小、显式的生命周期迁移。
- `ProjectStatus` 与 `TaskStatus` 使用字符串枚举，提供稳定的序列化值。
- 模型使用标准库 `dataclass`，保持不可变，并通过 `to_dict` / `from_dict` 提供 JSON 兼容的数据契约。
- 时间字段必须包含时区；标识、名称、路径和描述只做无 I/O 的基础校验。
- Domain 层不检查路径是否存在，也不访问文件系统、网络、Git、数据库或 AI 服务。

## 原因

标准库 dataclass 足以表达当前契约，无需在基础阶段引入第三方运行时依赖。不可变对象和显式状态迁移可以降低意外修改风险，使测试和后续适配更可预测。

## 后果

正面影响：

- 后续能力共享统一术语与序列化格式。
- 领域层可独立测试，不依赖基础设施。
- 状态和时间不变量在系统边界前即可验证。

限制：

- 当前序列化仅面向内存和字典，不代表数据库或 API 方案。
- 当前模型不负责发现项目、分析代码或持久化数据。
- 若未来需要演进字段，必须通过新的 ADR 说明兼容策略。
