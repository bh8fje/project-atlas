# ADR-0004：无内容读取的项目结构分析

- 状态：Accepted
- 日期：2026-08-23
- Task：TASK-005

## 背景

项目发现只能回答“项目在哪里”，后续历史、知识地图和 AI 上下文还需要统一的项目组成描述。结构分析会接触更多文件系统条目，因此必须限制深度和资产数量，并与源码内容分析、Git 历史及稳定身份明确解耦。

## 决策

建立 `ProjectStructureAnalyzer`、`StructureAnalysisScope` 与 `ProjectStructure`：

- 分析器接收已存在的 `Project`，只读取目录条目和文件元数据。
- 生成目录、普通文件、文档、源码和配置类型的 `ProjectArtifact`。
- 使用 `CONTAINS` 关系表达 Project、目录与文件的层次组成。
- 根据明确的文件名和扩展名生成可替换的技术标签。
- 输出资产类型计数，提供最小项目组成摘要。
- 默认限制最大深度和最大资产数，跳过依赖、构建、缓存目录和符号链接。

## 边界

- 不读取源码或文档内容，不进行语义分析。
- 不调用 Git，不读取 branch、commit 或历史。
- 不生成稳定 Project 或 Artifact 指纹；资产 ID 为单次分析使用的一次性 UUID。
- 不持久化，不调用 AI，不提供 API、Dashboard 或 UI。
- 技术标签是基于标记文件的候选描述，不代表完整技术栈判定。

## 后果

正面影响：

- 后续能力获得稳定、可序列化的结构报告。
- 文件系统访问有明确深度、数量和链接边界。
- 结构分类与 Domain Asset 模型保持一致。

限制：

- 不读取文件内容，因此无法识别隐藏在源码中的框架或依赖。
- 技术标记规则需要通过后续 Task 显式演进。
- 多次分析的临时资产 ID 不保证一致。
