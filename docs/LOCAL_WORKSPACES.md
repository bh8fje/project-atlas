# 本地项目目录管理

Project Atlas 可以识别指定目录下的软件项目，并在本机服务运行期间按设定间隔检查项目结构是否发生变化。

## 启动

首次使用先安装 Dashboard 依赖：

```bash
npm --prefix dashboard install
```

之后在仓库根目录运行：

```bash
./scripts/start-local.sh
```

打开 `http://localhost:3000/#workspaces`。此命令会同时启动本机服务和 Dashboard；关闭命令后，自动检查也会停止。

## 选择目录

1. 进入“项目目录”。
2. 点击“选择目录”。
3. 在操作系统目录选择器中选择一个项目上级目录；提示语言与当前界面语言一致。
4. Project Atlas 立即执行首次项目识别，并显示识别到的项目。
5. 点击项目名称，可查看最近一次本机检查得到的路径、技术栈、变化状态和资产分类。

系统通过 `.git`、`pyproject.toml`、`package.json`、`Cargo.toml`、`go.mod` 等基础标记识别候选项目。默认发现深度为四层，不跟随符号链接，并排除常见依赖、缓存和构建目录。

## 检查变化

- “立即检查”会马上重新识别项目并比较结构指纹。
- “自动检查”需要用户明确开启，可选择 15、30 或 60 分钟间隔。
- 页面每 10 秒读取一次本机最新结果，以显示后台检查完成后的变化。
- 结果包括项目总数，以及最近一次检查发现的新增、变化和移除数量。
- 单个项目超过 10,000 项结构检查上限时会标记为“超过当前检查范围”，其他项目仍会继续识别。受限项目不统计资产数量，也不生成完整结构指纹。

这里的“自动检查”是定时比较项目结构元数据，不是操作系统级实时文件监听，也不会读取文件内容或分析 Git 提交。

## 项目详情

项目详情是最近一次本机检查结果的展开视图，不是 AI 分析。完整检查的项目会显示技术栈及资产分类数量；受限项目会说明限制，但不会展示不完整的统计。打开详情不会再次扫描目录，也不会修改项目。

## 本地数据与移除

默认登记信息保存在：

- `~/.project-atlas/workspaces.json`
- `~/.project-atlas/workspace-state.json`

这些文件只保存已选目录、检查设置、项目基本资料和结构指纹。点击“移除”只删除上述登记信息和检查记录，不删除、移动或修改目录中的任何文件。
